## What exists
- Dev-only QA harness `window.__qa` (`src/dev/qaHarness.ts`): presses real key events (`tap`, `drive`, `goto`). It is loaded only in `npm run dev`.
- Phaser 3.90.0 + TypeScript 5.9.3 + Vite 7.3.7 + Vitest 4.1.11, all pinned exactly in `package-lock.json`.
- Scripts: `dev`, `build`, `typecheck`, `test`, `preview`.
- `BootScene` generates procedural textures, then `TitleScene` shows the eclipse logo, a rotating clock ring and the title.
- `clampDelta` (GDD §11, 0.05 s max step) with unit tests.
- **`RoomSim`** (`src/game/systems/RoomSim.ts`): deterministic rules for one chamber attempt (movement, ignition, gate, goal, stopwatch). `GameScene` only reads input and renders it, and tests drive it directly (`tests/helpers/drive.ts`) to prove rooms are solvable.
- Pure systems with tests: movement with normalized diagonals and slide-along-wall collision, 58 px ignite range, door conditions with no-trap closing, star scoring.
- Room 1 data. Each exit wall is generated by `exitWall()`, and `levels.test.ts` checks that the doorway is the only way to the goal.
- `GameScene`: dark room that lights up on ignition (bloom, embers, room light, radial pulses, `BEACON LIT`), lattice gate that retracts, condition badges, exit portal, HUD (chamber, hearts, clock, mute), pause on `Esc` or window blur, `R` restart, `M` mute, clear overlay with stars.
- **Echo (G3):** `EchoSystem` records the keeper every 0.1 s on its own clock (61 points = 6 s). `Q` replays the last 6 s as a looping cyan echo that lerps between samples and fades 0.15 s at each loop boundary. A short history is padded at the front so playback is always 6 s. The echo casts a cyan-edged shadow that powers runes like the keeper's, and nothing else. HUD: a MEMORY ring with `Q` ready state and a 6-second timeline strip. Continuous runes wear a dashed outer ring. Each level has an `echo` flag (room 3 onward).
- Hints have `show` (`start` / `ignite`) and `hide` (`ignite` / `runes` / `echo`).
- Docs: GDD, trailer shotlist, master prompt, QA checklist, competition rules summary, originality log.

## Bugs found in browser QA
- **Quick `E` taps were ignored (fixed).** Phaser processes all of a frame's key events together, so a keydown and keyup inside one frame cleared `JustDown` before `update()` saw it. Action keys (`E`, `R`, `Esc`, `M`, `Enter`) now use `keydown-*` events that queue into a set, which `update()` drains once per frame.

- **Glows turned white in Canvas mode (fixed).** Phaser's Canvas renderer ignores tints, so glows and embers are now generated already colored (`glowKey()`, `sparks` frames). The shadow also sets a solid fill, because Canvas ignores gradients.
- **WebGL failing mid-boot left a dead page (fixed, not force-tested).** Under memory pressure the browser made a WebGL context, then a Phaser shader or framebuffer failed. `Phaser.AUTO` does not fall back in that case. `main.ts` now catches a boot error and restarts once on Canvas. `?renderer=canvas` forces Canvas for testing.

## Decisions made
- **Engine stays on Phaser 3** (3.90.0, last 3.x) even though Phaser 4 is out, because the GDD and master prompt fix Phaser 3.
- **Naming:** the code uses `runes` (as in the GDD data contract). The GDD's "glyph" means the same thing.
- **Vite `base: './'`** so the same build works on GitHub Pages, Netlify or Vercel.
- **Hints are data:** each hint has a position and `beforeIgnite` / `afterIgnite`. An `E` key cap appears over any unlit brazier in range, so rooms need fewer text hints.
